## 記事の概要

このたび、Astroで構築しCloudflareのWorkders & Pages で運用していたブログを「はてなブログ」へ移行した。

移行の経緯、移行に際して行った作業、はてなブログでの設定、そしてそのときに自分が何を考え、何を選んだのかを、記録として残しておく。

後になって振り返るときのための備忘録でもある。

## ブログ移行の経緯

### 1. Bloggerの時代

ブログを最初に始めたときのプラットフォームは Blogger だった。Google が提供するサービスであったが、恐らく彼らは早くから見抜いていたのだろう。

ブログは早期に廃れる、と。

その証拠に、Blogger はアップデートがほとんど行われず、進化の著しい Web の世界では古代の化石のような存在になっていった。

何とか時代に合わせたサイトになるよう、手作業でカスタマイズを重ねながら使い続けた。しかし、ある時ふと気づいてしまった。

> 鋭い方は気が付いたと思う。標準機能をいかに削るかがBloggerの攻略ポイントであり、そんなサービスは異常だと思う。<br>
> Web標準に影響力のあるGoogleと同じグループに属するサービスにもかかわらず、改善・改良の回数は乏しく、広報は長らく無報、公式コミュニティは回答のない質問が屍となって山を築いている。<br>
> なぜBloggerを使い続けているのかと言えば、はじめてBlogを作ったのがBloggerぐらいしか理由が見つからない。<br>
> -- [PageSpeed Insightsの4項目でオール100を達成・実施事項まとめ【Blogger】 - neputa note](https://www.neputa-note.net/entry/2024/04/25/blogger-pagespeedinsights) より

さすがに潮時だと悟り、自由度MAXを求め自作することにした。

### 2. Astro & Cloudflare Workers & Pages の時代

Astro という静的サイト向けフレームワークを使い、Cloudflare Workers & Pages でビルドし公開する構成を採用した。

- [BlogをBloggerからAstroへ移行した - neputa note](https://www.neputa-note.net/entry/2024/07/01/migrated-blogger-to-astro)

かなり自由かつ快適にブログを書き散らし、とっても満足していた。

### そして今、はてなブログへ

そしていよいよ、本題の Astro ブログからはてなブログへの移行について書く。

昨年あたりから、このブログは視覚障害に関する話が増えていた。「錐体桿体ジストロフィ」という、目の網膜細胞が変性する遺伝子の病気が見つかったのだ。

- [視覚に関する記録 09 - 錐体桿体ジストロフィと診断された日 - neputa note](https://www.neputa-note.net/entry/2026/04/14/my-records-of-my-vision-09)

医師からは、「ゆっくりと徐々に視力を失いますよー」と言われている。そうなると、自由の代償である「サイトとインフラのメンテナンス」が負担になってしまうのではないか。

余計なことを書いてバンされたり、業績が悪くてサービスのアップデートが止まったり、制約のあるブログサービスは嫌だ。

とはいえ、背に腹は代えられない。自由を手放すことにした。

なぜ数多あるブログサービスのなかで「はてなブログ」か。決め手は [Hatena-Blog-Workflows-Boilerplate](https://github.com/hatena/Hatena-Blog-Workflows-Boilerplate) 。

これについて後述する。

## はてなブログを選んだ理由

### 移行先の選考ポイント

以下の要件を Gemini に問い、候補を出してもらった。

- ブログの機能追加、ネットワーク管理がプラットフォーム側で完結する（ドメイン管理を除く）
- 記事や画像データを手元で管理できる
- マークダウンで記述できる
- VSCode と Neovim の拡張機能を使って記事を書きたい

### VSCodeとVimにこだわる理由

目が見えづらくなるにつれて、PC 操作で最初につまずいたのが「マウスのカーソルどこよ？」問題だった。設定でカーソルサイズを最大にし、色をショッキングピンクに変えても、なかなか見つけられなくなってしまった。

こうなると、ショートカットキーがないツールは使いづらい。Web ページは Firefox に [Vimium](https://vimium.github.io/) を入れて何とか操作しているが、サイトによってはボタンやフォームが認識できない場合があり、安定しない。

VSCode はショートカットキーを自由に設定できるし、Neovim 拡張機能でテキスト入力・編集をマウスなしで行える。安定しない Web 上のエディタより、私にとって操作しやすい環境だ。何より、使い慣れている環境は最も安心できる。

そのうち視力が完全になくなっても、ショートカットキーだけで操作が完結していれば、スクリーンリーダーによる操作へスムーズに移行できるだろう。

### 移行先をはてなブログに決定する

Hashnode、Zenn などがまず候補に挙がった。しかし、私のブログは技術記事も一部あるものの、ほぼ「情報価値ゼロの記事」で溢れている。ゼロブログだ。

もっと気楽なプラットフォームで、要望に沿うものを探すと、Gemini が返してきたのが「はてなブログ」だった。

Hatena-Blog-Workflows-Boilerplate を利用することで、こちらの要望をすべて満たせるという話しだ。

Hatena-Blog-Workflows-Boilerplate（以降、Boilerplate）とは何か。

Boilerplateを利用すると、記事の管理はGithub、はてなブログとの連携はGithub Actionsで行える。またGithubの操作はCLIやVSCodeの拡張機能でも可能だ。

> GitHub 上で、はてなブログとの記事の同期、下書きの作成・編集・公開、公開記事の編集などを行うことができます。下書きの作成時にプルリクエストが作成されるため、記事のレビューなどの業務のワークフローに組み込むことが容易になります<br>
-- [hatena/Hatena-Blog-Workflows-Boilerplate](https://github.com/hatena/Hatena-Blog-Workflows-Boilerplate) より引用

もともとは法人やチーム向けのツールであるとのことだが、これなら VSCode 上で記事の作成・更新から投稿まで完結できる。

私が求めていたブログサービス、それは「はてなブログ」だった。

## 移行に向けた作業

### 移行データの生成

AstroではMDXというマークダウン拡張フォーマットを使用していた。

まずは、はてなブログのマークダウン仕様を [こちら](https://github.com/hatena/Hatena-Blog-Workflows-Boilerplate#%E3%82%AB%E3%82%B9%E3%82%BF%E3%83%A0url%E3%82%92%E6%8C%81%E5%AE%9A%E3%81%99%E3%82%8B) で確認した。

MDX で使っていたブログカードや埋め込み動画、SNS 投稿などを、[はてな記法](https://help.hatenablog.com/entry/text-hatena-list) を参考に変換ルールとして決めた。

あとはスクリプトを作成し、はてなブログ用のマークダウンファイルを生成した。

### はてなブログへのアップロード

ここで最初の壁にぶつかった。

Boilerplate の `create_draft` アクションを実行すると、`draft_entries` ディレクトリにマークダウンファイルが作成される。フロントマターの `Draft` フラグを削除または `false` に修正し、プルリクエストをマージすると、はてなブログへ投稿される。

しかし、こちらで生成したマークダウンファイルを `draft_entries` に配置し、`Draft` フラグを `false` に設定しても、はてなブログへの反映処理でエラーが発生した。

Boilerplate のアクションで生成されたファイルには、編集画面用とプレビュー用の URL が発行されている。こちらで作成した移行用のファイルにはそれがない。ここがエラーの原因だったようだ。

一括移行は断念し、VSCode に備わっている GitHub Copilot と相談しながら、自動化できる部分をスクリプト化して、半自動で 340 件ほどの記事をはてなブログへ反映させた。

現在のリポジトリは [neputa/neputa-note-hatenablog: 個人日記 in はてなブログ](https://github.com/neputa/neputa-note-hatenablog) 。

## はてなブログの設定内容

すべての記事と画像などをはてなブログに持ってきた次は、ブログの設定をいくつか行った。

### 独自ドメイン

Blogger 時代に取得した現在のドメインは、XServer Domain で取得したものだ。前の環境ではネームサーバを Cloudflare に移し、そこで DNS レコードを含めた設定をほぼすべて管理していた。

今回の移行に伴い、Cloudflare は不要になると思っていたが、そう簡単ではなかった。

このブログの正式なドメインは `www.neputa-note.net` である。Cloudflare では、`www` のないドメインへのアクセスをリダイレクトルールで `www` ありのサブドメインへ転送していた。はてなブログにはリダイレクト機能がない。

そのため、Cloudflare 環境は残し、次のように設定した。

- `www.neputa-note.net` - CNAME / DNS のみ
- `neputa-note.net` - A / プロキシ接続

`www` が付いた場合はそのままはてなブログへ通し、`www` が付かない場合のみページルールで `www` ありのサブドメインへリダイレクトする形で、はてなブログへ通すようにした。

### URLパスの変更対応

Astro ブログとはてなブログでは記事の URL パスを統一できなかった。はてなブログはドメインの後に `entry/` が入る。

Cloudflare でリダイレクト用の Worker を設定しようかと思ったが、サブドメインをプロキシ接続すると、はてなブログと Cloudflare の間で SSL 証明書の衝突が発生するという話だった。

> ここがオレンジ色の雲（プロキシ済み）になっていると、Cloudflare のセキュリティ機能がはてなブログの SSL 証明書と衝突し、「接続がプライベートではありません (NET::ERR_CERT_COMMON_NAME_INVALID)」というエラーが永続的に発生します。<br>
> -- [【2025年】はてなブログに Cloudflare で独自ドメインを設定する最安手順とエラー解決法 - Compass note](https://compass-note.hatenablog.com/entry/hatenablog-cloudflare-custom-domain#Step2-%E3%81%AF%E3%81%A6%E3%81%AA%E3%83%96%E3%83%AD%E3%82%B0%E3%81%A7%E7%8B%AC%E8%87%AA%E3%83%89%E3%83%A1%E3%82%A4%E3%83%B3%E3%82%92%E8%A8%82%E5%AE%9A%E3%81%99%E3%82%8B) より引用

さらに、はてなブログには 301 リダイレクト機能がないようだった。今や AI 登場の時代でもあり、検索の時代でもないし、過去のサーチエンジンの評価などを引き継げなくてもそこまで問題ではないだろう。

とはいえ、せっかく訪れてくれた方に 404 Not Found を突き付けるのも申し訳ない。そこで、ある程度対象を絞ってスクリプトでリダイレクトをかけることにした。

コードは [こちら](https://github.com/neputa/neputa-note-hatenablog/tree/main/assets/scripts/redirect) である。

使い方は、テキストファイルに新旧 URL の対応リストを用意し、それをもとにシェルスクリプトで JS を生成する。これをはてなブログのデザイン設定のヘッダに埋め込む、という流れだ。

### ブログテーマ

- ダークテーマ対応
- シンプルなデザイン

このブログを最も読むことになるのは私自身だ。私は白背景に黒い文字が読めなくなってしまっている。とはいえ、訪れてくれた読者の方々には、おそらく白背景に黒文字のほうが読みやすいだろう。だから、ダークテーマは最も重要な条件だった。

シンプルでとても美しいと感じるデザインで、気に入っている。
