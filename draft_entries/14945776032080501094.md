## 記事の概要

[前回の記事](https://www.neputa-note.net/entry/2026/09/19/the-importance-of-accessibility)で言及したWebアクセシビリティに関連し、今回このブログを少しだけ改善してみた。

前提として、私は視覚障害者であり、今回の改善はあくまで**視覚障害**を対象にしている。`iPhone`の`VoiceOver`を使用し、問題なく閲覧できることを目指すものとする。

調査には`Google Chrome`の`Lighthouse`を使用した。改善できた点はもちろんのこと、至らなかった点も交えて記録する。

また、一連の作業において`ChatGPT`をフル活用した。

## 環境

- ブログサービス: はてなブログ
  - テーマ: [CodeFocus](https://codefocus.hatenablog.jp/)

## 改善点の詳細

### 改善点の抽出手順

今回おこなった改善点を抽出する具体的な手順を以下に示す。

1. `Google Chrome`でこのブログのトップページを開き、`デベロッパーツール`→`Lighthouse`で「ページ読み込みを分析」を実行する
1. `Lighthouse`の結果を`HTML`または`JSON`形式で保存する
1. `ChatGPT`に保存した`Lighthouse`の結果を入力し、主にアクセシビリティの改善点を抽出する
1. 抽出した内容に基づき、修正プランとテストプランを`ChatGPT`に作成してもらう

> [!WARNING]
> Chromeに拡張機能を入れている場合は、Lighthouseの結果に影響を与えることがあるため、プライベートウィンドウで実行することを推奨する

### 抽出結果の詳細

アクセシビリティに関連する問題点は以下の通りだった。

1. entry-thumb-link にアクセシブルな名前がない
2. <main> ランドマークがない
3. 小さすぎるリンク・ボタンがある
4. Hatena Star の iframe に title がない

個々の問題点について、以下に詳細を示す。

#### 1. entry-thumb-link にアクセシブルな名前がない

ブログのトップページには、記事のタイトルとサムネイル画像が表示されているが、サムネイル画像へのリンク（entry-thumb-link）にはアクセシブルな名前が設定されていない。

これを`VoiceOver`でフォーカスを当てると、「リンク」とだけ読み上げられ、何のリンクなのかが分からない。

#### 2. <main> ランドマークがない

現状のメインコンテンツ部分を包んでいるコードは以下のようになっている。`main`タグや`role`属性が設定されておらず、ランドマークとして認識されていない。

`VoiceOver`では、「コンテナ」という単位で素早くページ上を移動することができるが、`main`ランドマークが設定されていないと、前後のランドマークへの移動が困難になる。

```html
<div id="main-inner">
  <!-- メインコンテンツ -->
</div>
```

[https://developer.mozilla.org/ja/docs/Web/Accessibility/ARIA/Reference/Roles/main_role:embed:cite]

#### 3. 小さすぎるリンク・ボタンがある

`Lighthouse`が基準としている24px × 24pxという数値は、`WCAG 2.2`の「Target Size (Minimum)」の推奨値である。現在、この基準を下回るリンクやボタンが21か所存在した。該当箇所は以下の通りである。

- カテゴリーリンク / archive-category-link
- はてなブックマーク / bookmark-widget-counter
- プロフィールリンク / hatena-id-link
- 月別アーカイブ / archive-module-month-title

なかでも、`bookmark-widget-counter` は 5.5px × 17.5px と特に小さく、操作が困難である。

#### 4. Hatena Star の iframe に title がない

はてなブログには、記事に対してユーザーが評価を行うことができる「Hatenaスター」という機能がある。そのスターを追加する`iframe`が埋め込まれているが、`title`属性が設定されていない。

個別記事のページであれば問題ないが、トップページのように複数の記事が一覧表示される場合、どの記事のスターなのかを`VoiceOver`が判別できない。

### 改善内容

4つの改善点について、以下の方向で対策を行った。

1. entry-thumb-link にアクセシブルな名前がない
    - JavaScriptで`entry-thumb-link` に記事タイトルを含むアクセシブルな名前を設定する
2. <main> ランドマークがない
    - JavaScriptで`main`ランドマークに相当するdiv要素に`role="main"`を設定する
3. 小さすぎるリンク・ボタンがある
    - CSSでリンク・ボタンのサイズを24px × 24px以上に調整する
4. Hatena Star の iframe に title がない
    - はてなスターをブログに表示しない

それぞれの対策について、以下に詳細とその理由を示す。

#### 1～2の対策について

- 根本的な修正を行うには、テーマのテンプレート自体を編集する必要がある
- これを回避するために、JavaScriptで動的に属性を追加する方法を採用した

### 3の対策について

- 根本的な修正を行うには、はてなブログの標準モジュールを修正する必要がある
- そこは手出しできないため、CSSでサイズを調整することで対応した
- 文字自体を24pxにするのではなく、クリック可能な領域を24×24px以上になるよう調整した

### 4の対策について

- 1～2の対策と同様の手法で対策することは可能であるが、今回ははてなスター自体を表示しないことにした
- はてなスターは、アクセシビリティ以外にもページの読み込み速度への影響が大きい問題も抱えている
- スターによる評価をもらえる楽しみは失われるが、アクセシビリティとページの読み込み速度の向上を優先した

### 成果物

動的に属性を追加するJavaScriptのコードや、サイズ調整を行うCSSのコードを以下に示す。

いずれも`ChatGPT`に作成してもらった。

#### JavaScriptによる属性追加

以下のコードを、デザイン > カスタマイズ > フッタ に追加しておくことで、`DOMContentLoaded` イベントで実行される。

```javascript
(function () {
  function fixMainLandmark() {
    const main = document.getElementById('main-inner');

    if (main && !main.hasAttribute('role')) {
      main.setAttribute('role', 'main');
    }
  }

  function fixEntryThumbLinks() {
    document.querySelectorAll('a.entry-thumb-link').forEach(function (link) {
      if (link.getAttribute('aria-label')) {
        return;
      }

      const entry = link.closest('.archive-entry');

      if (!entry) {
        return;
      }

      const title =
        entry.querySelector('.entry-title a') ||
        entry.querySelector('.entry-title') ||
        entry.querySelector('h2 a') ||
        entry.querySelector('h3 a');

      if (!title) {
        return;
      }

      const text = title.textContent.trim();

      if (text) {
        link.setAttribute(
          'aria-label',
          '記事「' + text + '」を読む'
        );
      }
    });
  }

  function init() {
    fixMainLandmark();
    fixEntryThumbLinks();

    const observer = new MutationObserver(function () {
      fixMainLandmark();
      fixEntryThumbLinks();
    });

    observer.observe(document.body, {
      childList: true,
      subtree: true
    });
  }

  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', init);
  } else {
    init();
  }
})();
```

#### CSSによるサイズ調整

以下のコードを、デザイン > カスタマイズ > デザインCSS に追加する。`Lighthouse` で指摘があった4か所の要素に対して調整を行う。

```css
.archive-category-link,
.hatena-id-link,
.archive-module-month-title {
  display: inline-flex;
  align-items: center;
  min-height: 24px;
  padding: 4px 6px;
}

.bookmark-widget-counter {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  min-width: 24px;
  min-height: 24px;
}
```

## まとめ

結果として、当初`Lighthouse`で指摘されていた問題は無事に解消された。85点だったスコアも100点に向上した。しかし、今回の対応はあくまで指摘を回避するためのものであり、根本的な解決ではない点は留意しておく必要がある。

個人的な希望としては、サムネイルとブログタイトルは一つのリンクとしてまとめ、`VoiceOver`のフォーカスでタイトルを読み上げるようにすれば、興味がある記事までスムーズにアクセスできるようになると思う。その他、ランドマークの設定もWCAGの推奨に従ったものへと修正できればと考えている。

そうなると、テーマテンプレートに手を入れる必要がある。いま使用させてもらっているテーマをフォークし、自分でアクセシビリティに最適化するか。それだとメンテナンスの負担から逃れるため、はてなブログへ移行した意味がない。どうしたものか。

Webアクセシビリティの知識を深め、的確な修正案を提示できるようになり、issueやPull Requestを通じてテーマ開発者と協力できるようになるのが理想的かもしれない。

とりあえず今回は、小規模ではあるがWebアクセシビリティを意識した取り組みを行った。今後も継続的に改善を重ねていきたいと思う。
