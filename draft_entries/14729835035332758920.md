## 1. はじめに

* メールクライアントソフト「Thunderbird」のアドオンを初めて開発し、公開した
* Thunderbird上で現在の操作画面に応じたショートカットキー一覧を表示するシンプルなアドオン
* この記事では、開発のきっかけから公開までの過程を紹介する

### 作成した拡張機能

* 名称: ContextKeys
* 概要: 現在の操作画面に応じたショートカットキー一覧を表示する拡張機能
* バージョン: 1.0.0
* 公開先: [ContextKeys :: Thunderbird向けアドオン](https://addons.thunderbird.net/ja/thunderbird/addon/contextkeys/)
* Github: [neputa/ContextKeys](https://github.com/neputa/ContextKeys)

[:contents]

## 2. 開発環境

* OS: Windows 11 Pro
* エディタ: Visual Studio Code
* バージョン管理: GitHub
* AI支援: GitHub Copilot
* Thunderbird: 最新安定版

## 3. Thunderbirdを使い始めたきっかけ

* 進行性の視覚障害が発症し、PC環境をスクリーンリーダー（音声読み上げ）中心の操作環境へ移行を進めている
* 具体的には、スクリーンリーダーユーザーの間で広く利用されている操作方法やツールへの移行を進めている
* その一環として、メールクライアントをWeb版GmailからThunderbirdへ移行した
* 万が一Googleアカウントにアクセスできなくなった場合でも、メール環境を維持できる目的もあった

## 4. Gmailのようなショートカットキー一覧が欲しい

* Thunderbirdを使いこなすために、キーボードショートカットを覚えたいと思った
* 操作方法を覚えるには、必要なときにショートカットキーを確認できる仕組みが欲しい
* Gmailには Ctrl + Shift + / でショートカットキー一覧を表示する機能がある
* Thunderbirdにも公式のショートカットキー一覧ページがWeb上に用意されている
* Thunderbird上で、現在の操作画面に応じたショートカットキー一覧を表示できないかと考えた
* 自分で拡張機能を開発することにした

## 5. 開発する拡張機能の仕様を考える

### 開発する拡張機能の基本仕様

* 現在の操作画面に応じたショートカットキー一覧を表示する
  * メール
  * カレンダー
  * アドレス帳
  * ToDo
* ショートカットキーで一覧を呼び出せるようにする
* Thunderbird公式サイトに掲載されているショートカットキー情報を活用する
* スクリーンリーダーで利用しやすく、視覚障害者ではないユーザーにも使いやすい設計を目指す

## 6. VSCodeとGitHub Copilotで拡張機能を開発

### 開発環境の準備

* 開発環境としてVSCodeを使用する
* コードの実装は、主にGitHub Copilot（以降、Copilot）を活用する
* 拡張機能をテストできるようにThunderbirdに開発用プロファイルを作成する
  * [プロファイルマネージャーで Thunderbird プロファイルを作成または削除する | Thunderbird ヘルプ](https://support.mozilla.org/ja/kb/profile-manager-create-and-remove-thunderbird-profiles)

### 開発の進め方

#### 要件整理と要件定義書の作成

* 要件を箇条書きで整理する
* 要件をCopilotに渡し、要件定義書を作成してもらう
* これをもとに、Copilotと対話しながら必要な追加情報を補完する

#### 実装と修正の繰り返し

* 要件定義書をもとに、Copilotに開発作業をフェーズ分けしてもらう
* フェーズごとに実装とテストを繰り返す
* テストは、開発用に作成したThunderbirdのプロファイル環境で行う
* 実装中に発生した問題や不具合をフェーズごとに解決しながら開発を進める
* コミットを適宜行うようにCopilotにあらかじめ指示しておく
* 実装が完了したら、拡張機能をパッケージ（.xpiファイル）化して公開準備を行う

#### Thunderbirdでのデバッグ手順

1. Thunderbirdを起動し、開発用プロファイルを選択する
2. メニューまたは設定から「アドオンとテーマ」を開く
3. 画面右上の歯車アイコンをクリックし、「アドオンをデバッグ」を選択し、デバッガーを開く
4. 「一時的なアドオンを読み込む」ボタンをクリックし、開発中の拡張機能のディレクトリから manifest.json ファイルを選択する
5. 実際のThunderbird上で拡張機能の動作を確認する
6. 不具合があれば修正し、再度拡張機能を読み込んでテストする
7. ログはメニューの「ツール」→「開発者ツール」→「マルチプロセスブラウザツールボックス」のコンソールから確認できる
   * リモートデバッグ接続要求のダイアログが表示されたらOKをクリックする

## 7. addons.thunderbird.netで公開する

1. Mozillaの開発者アカウントを作成する
   * [開発者センター :: Thunderbird向けアドオン](https://addons.thunderbird.net/ja/developers/)
2. 登録アカウントでログインし、自分のアドオン→新しいアドオンを登録ボタンをクリックする
3. 登録画面1: 最初の設問「このバージョンの配布手段」の2択はどちらでも良いが、すぐ公開されて問題ないのでデフォルトままとした
4. 登録画面2: 2つある設問を以下のとおり設定し、続けるボタンをクリックする
   * バージョンをアップロード→ファイルを選択ボタンで、作成した.xpiファイルをアップロードする
   * Which applications is this version compatible with? は、Thunderbirdを選択する
5. 登録画面3: 「ソースコード提出ポリシー を確認してください。 以下のいずれかを使っていますか？」の設問に対し、特に該当するものがなければ「いいえ」を選択し、続けるボタンをクリックする
6. 登録画面4: 以下2つの欄を入力し、登録ボタンをクリックする
   * リリースノート: 拡張機能の機能について簡単に記載する
   * 審査担当へのメモ: 特殊な実装が無ければ空欄
7. 登録が完了すると、審査が行われ、問題がなければ公式サイトに公開される

あとは適宜、公開ページの掲載情報を充実させることで、ユーザーに拡張機能の内容を正しく伝えられるようにする。

## 8. おわりに

今回初めてThunderbirdの拡張機能を開発・公開した。

Webメールやスマホアプリの普及でPC向けのメールクライアントを使う人は減っている。私も視覚障害者にならなかったらGmailを使い続けていたかもしれない。

そんないきさつではあったが、スクリーンリーダーユーザーの間で利用実績が多いということで、Thunderbirdを使うことになった。そして、初めてアドオン開発に挑戦するにいたった。

ケガの功名のような形ではあるが、とても楽しい経験となった。

また、今回の開発において私が行ったのは、AIが意図したとおりにコードを生成してくれるようにテキストを入力し、動作確認を行っただけだった。

AIが書いたコードを読むことはあったが、自分では一行も書いていない。

開発環境の大きな変化を感じる体験でもあった。

こういう形であれば、今後も趣味で開発を続けられるかもしれない。

Thunderbirdを使い始める稀有な方がいたら、よかったら使ってみてほしい。
